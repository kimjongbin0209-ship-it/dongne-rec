# 서빙 벤치 — NYC, R=3km, SASRec-S2 (mixed) seed 0

`make bench`로 생성된 파일이에요. 프로세스 내 측정, batch=1, test 요청 1,083건 (warmup 별도), macOS-27.2-arm64-arm-64bit.
후보 N=200, Stage 1-b 쿼리 = 최근 3개 장소 임베딩 평균.

torch 인코더는 FAISS와 한 프로세스에서 OpenMP 런타임이 충돌해서(macOS) numpy 검색으로 재요. 두 검색의 후보 집합은 같아요.

아이템 임베딩 10.0MB(fp32)는 모든 구성에서 후보 점수 계산에 공통으로 써요. ONNX 변환 오차 max|onnx − torch|: fp32 6.6e-06, int8 9.6e-02.

## 표 5. 파이프라인 구성 (인코더 onnx-fp32, 단일 스레드)

| 구성 | 재랭킹 후보 수 (median) | 정답이 후보에 남은 비율 | 1-a / 1-b / 2 p50 (ms) | E2E p50 / p99 (ms) | NDCG@10 | 오프라인 기준 |
|---|---|---|---|---|---|---|
| 2단계 (FAISS) | 200 | 34.8% | 0.06 / 0.19 / 0.78 | 1.05 / 1.44 | 0.2182 | E4 0.2209 |

| 지리 필터 없음, 전체 카탈로그 재랭킹 | 9785 | 100.0% | 0.06 / 0.00 / 1.73 | 1.78 / 2.83 | 0.3322 | E3 0.3322 |

- 오프라인 기준: 같은 체크포인트의 test 0.2209 (E4, 동네 전체 랭킹), 0.3322 (E3, 전체 랭킹). 오프라인은 동점 기댓값, 서빙은 실제 정렬이라 아주 작은 차이는 있을 수 있어요.
- 2단계 (FAISS): 반경 안 장소 median 1208개, 그중 N개 초과로 1-b가 후보를 줄인 요청 69.7%, 반경을 넓힌 요청 0.3%.
